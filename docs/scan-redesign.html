A simpler component scan

Today the plugin asks you to prepare too much, uses 8 small steps, and labels things in ways that are hard to read. This proposal keeps what works (reading your light and dark components, drafting the tokens, applying them back) and cuts it to 3 clear screens in a wider window. The screens below use your Control example. Colours are sample values.

What you found confusing, and the fix
Not clear what to select, or whether to move thingsSelect the 2 component sets, light and dark, wherever they are. Nothing to move, wrap or rename.
Naming them "light" and "dark" made the tokens start with "light-"The plugin takes the component name from the set, drops words such as light, dark and copy, and lets you edit it. Every token name updates as you type.
The plugin guessed which one was dark from names and modesIt shows both side by side with a picture of each and asks you to check. If it guessed wrong, press Swap. It remembers your answer.
"L" and "D" labelsEvery colour is shown as a full "Light" and "Dark" pair, with the swatch, the primitive name and what the layer used before.
Layers had to be named surface, line, content or iconThe plugin works out the part from the layer itself (frame fill, stroke, text, icon) and you can change it from a menu. No renaming in Figma.
8 steps, and the result was hard to picture3 screens: Check, Token map, Finish. The token map is 1 grid of parts against states, like the matrix in the token namer.
Before you open the plugin

The only thing to prepare

  1. Make the component a component set with a State property: Default, Hover, Pressed, Disabled and so on. This is the one thing the plugin cannot guess.
  2. Duplicate the set for dark and change only the colours. Its name does not matter.

No layer renaming, no wrapping frames, no special names, no modes to set.

Decisions before I build it

  1. Is the 3-screen flow right, with the token map as a grid of parts against states?
  2. How should the plugin know which set is dark: guess and show Swap (recommended), or always ask you to pick?
  3. If a component set has no State property yet, should the plugin let you name each variant's state inside the plugin and add the property for you?
  4. Is a window about 880 by 640 pixels a good size?
